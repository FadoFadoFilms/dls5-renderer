# DLS5 Renderer — Fadó Fadó Films

Experimental **Unity 6 HDRP → DLSS 5 community video player → Unity HDRP** offline processing pipeline, including an RTX 2060 6 GB compatibility harness.

> **Status: v0.3 manager source prototype — not compiled/tested in a Unity 6.4 HDRP Editor.** The third-party DLSS neural renderer/runtime is not included. The included harness can download it separately from its upstream releases after user approval. This repository is public; do not commit film footage, paid assets or credentials.

## Windows quick start

On Windows 10/11, double-click **`START-FADOEXR-MANAGER.cmd`** from a full `dev` checkout. It verifies **Python 3.13 + Tkinter**, `ffmpeg`, `ffprobe`, and the media filters/codecs needed by this pipeline; missing dependencies are installed through `winget`. It checks for updates to a winget-managed FFmpeg once per week. Other Python versions and custom FFmpeg installations remain unchanged.

Use **`Tools/SETUP-DEPENDENCIES.cmd`** to install/check now (including a fresh FFmpeg update check), or **`Tools/CHECK-DEPENDENCIES.cmd`** for a read-only status check. Install logs stay under `%LOCALAPPDATA%\FadoEXR\PipelineManager\dependency-logs`. See [Windows setup instructions](Tools/README-WINDOWS-SETUP.md). **These Windows scripts have not yet been exercised on the user's PC.**

## Three components

| Directory | Purpose |
|---|---|
| `1 Unity Export/` | Copy `Assets/FadoEXR` into the original film's HDRP Unity project; capture `Clean`, `Reference`, and resolved colour/Volume settings. |
| `2 Player/` | Source for the Windows RTX 2060 offline video test harness and its installer. Build from the installer template and downloaded upstream runtime. |
| `3 Import/` | Copy `Assets/FadoEXR` into a separate matching HDRP project; reconstruct postprocessing and replay DLSS footage. |

`Tools/` contains the lossless EXR → FFV1 player interchange and video → PNG16 conversion; `Docs/` contains architecture, QA and next steps. Each Unity folder is an **Assets package**, not a complete new Unity project.

## Desktop Pipeline Manager (new experimental v0.3)

Run `START-FADOEXR-MANAGER.cmd` on Windows with Python 3 installed. It opens a desktop control panel to register **two separate Unity projects**, preview and safely update each `Assets/FadoEXR`, opt in to downloading the newest complete community player, convert EXR to lossless FFV1, run the diagnostic neural player, and stage completed shot grades and verified processed frames for the EXR Renderer. The importer now has a **Load latest Pipeline Manager handoff** button. Source shot media is *not* silently copied into Unity Assets, and the two Unity projects remain independent Git repositories.

**Read [Manager/README.md](Manager/README.md) for Windows setup, safety and current limits.** The initial manager is source-only (not an `.exe`), and Unity/Windows end-to-end QA is still required.

## First workflow to test

1. In your film project, install `1 Unity Export/Assets/FadoEXR`; use **Tools → Fado Fado → EXR Roundtrip → 1 - Capture film**. Capture one frame first.
2. Convert its new shot folder using `Tools/EXR-To-Player.cmd` (requires Python 3, FFmpeg/FFprobe). Keep the untouched EXR and reference.
3. Process the new lossless MKV with the experimental community DLSS video player; save to a **new** output file, preferably lossless.
4. Convert the processed video back to PNG16 using `Tools/Video-To-PNG16.cmd`.
5. Install `3 Import/Assets/FadoEXR` in a separate matching HDRP project, then use **Tools → Fado Fado → EXR Roundtrip → 2 - Restore in EXR Renderer**. Import grades, create SAFE/FULL profiles, and test one frame.

**Critical limitations:** a before-post-process EXR may already contain TAA or other earlier renderer effects; Unity HDRP compile, precise grade replay, real depth/motion buffers, and actually feeding those buffers to the third-party renderer are **not** yet validated or implemented. SDR conversion for this player is not HDR reversible. See `Docs/QA.md`.

## Local tests

Run `python -m unittest discover -s Tests -p "test_*.py" -v` from repository root. Structural checks and synthetic FFmpeg tests passed when packaged; **these do not replace Unity QA**.

## Source control

The root `.gitignore` excludes **nested** Unity `Library/`, `Temp/`, `Logs/`, `Obj/`, `UserSettings/`, local renders and IDE caches. Preserve Unity `.meta` files when Unity generates them; commit `Assets/`, `Packages/` and `ProjectSettings/` for any full Unity project subsequently added. The installer source's large `installer.c` is generated by `generate_installer.py`, not tracked. Avoid committing third-party neural-runtime binaries and private film files.
